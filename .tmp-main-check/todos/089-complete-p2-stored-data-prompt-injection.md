# Add data delimiters for stored content injected into prompts

## Problem Statement
Two code paths inject stored data verbatim into system prompts without sanitization or data-boundary delimiters, creating second-order prompt injection vectors:

1. **Conversation summary** (agent.rs:94-100): Compacted summary text injected into system prompt
2. **Reminder message** (agent.rs:324-329, 344-348): Reminder message interpolated into silent-mode system prompt and user message

Both paths allow data that was generated by Claude (or influenced by user input) to later appear as system-level instructions.

## Findings
- Conversation summary: user input → stored in conversations → summarized by compaction → injected into system prompt → influences future agent decisions
- Reminder message: LLM creates reminder via tool → message stored → fires later → interpolated into system prompt
- Per-customer assistant means "attacker" is typically the user themselves (low threat in Phase 1)
- Becomes higher risk in Phase 2 with multi-channel input from less-trusted sources
- Flagged by: Security Sentinel (Medium x2)

## Proposed Solutions

### Option 1: XML data delimiters (Recommended)
Wrap injected content in explicit data-boundary tags:
```rust
// Summary
system.push_str("\n## Conversation Summary\n");
system.push_str("<context type=\"summary\" trust=\"data\">\n");
system.push_str(&summary.content);
system.push_str("\n</context>\n");

// Reminder
format!(
    "The user asked to be reminded:\n<reminder-data>{message}</reminder-data>\n\
     Deliver this reminder using send_message."
)
```
**Pros:** Signals to Claude that content is data, not instructions
**Cons:** Not a foolproof defense against prompt injection
**Effort:** Small
**Risk:** Low

### Option 2: Strip markdown headings and known injection patterns
**Pros:** More aggressive defense
**Cons:** Complex sanitization, may strip legitimate content
**Effort:** Medium
**Risk:** Medium (over-filtering)
