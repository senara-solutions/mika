## Mika 1.0.0

Mika est une assistante qui travaille avec toi dans ton terminal. Elle se souvient de ce que tu lui dis d'une conversation à l'autre : les personnes de ta vie, tes engagements, tes préférences, les événements. Tout est rangé sur ta machine, dans une base SQLite sous `~/.mika/`.

Cette version est la première numérotée 1.0. Elle rassemble 942 commits de travail depuis la v0.12.2 de mai 2026.

### Ce que tu reçois

- **`mika`**, l'application en terminal : une conversation, avec la mémoire, les rappels et les commandes `/`.
- **`mika-spirit`**, le serveur HTTP du même agent, pour qui veut le faire tourner en service.
- Pour Linux et macOS, sur processeurs Intel/AMD (x86_64) et ARM (aarch64, dont les Mac Apple Silicon).

### Ce que Mika sait faire

- Garder une mémoire persistante, qu'elle met à jour elle-même.
- Suivre les personnes, les engagements, les préférences et les événements.
- Te rappeler une chose à l'heure dite, même après un redémarrage.
- Résumer les vieilles conversations pour ne pas perdre le fil.
- S'étendre par des skills, à installer avec `mika skills install`.
- Parler à plusieurs fournisseurs de modèles : Anthropic par défaut, et aussi OpenAI, OpenRouter, Groq, Ollama et d'autres.

### Installer

```sh
curl -fsSL https://raw.githubusercontent.com/senara-solutions/mika/main/install.sh | sh
```

Le script choisit la bonne archive pour ta machine, vérifie son empreinte SHA-256 et installe `mika` dans `~/.local/bin/`. Il te faut ensuite une clé de ton fournisseur de modèle, par exemple `export MIKA_ANTHROPIC_API_KEY=…`, puis lance `mika`. Au premier lancement, Mika crée `~/.mika/` et ouvre la conversation. Les skills fournies ont besoin de `jq` sur la machine.

### Vérifier ce que tu as téléchargé

Chaque archive est accompagnée de son empreinte (`.tar.gz.sha256`), d'une signature cosign (`.bundle`) et d'une attestation de provenance GitHub. Chaque binaire a aussi son SBOM, la liste de ses dépendances. Ensemble, ils prouvent que le fichier a été construit par ce dépôt, depuis ce commit. La marche à suivre est dans [`docs/release-verification.md`](https://github.com/senara-solutions/mika/blob/main/docs/release-verification.md).

### Ce qui n'est pas dans ces binaires

- Le tableau de bord web : dans un binaire de release, `/dashboard/` affiche une page « désactivé ».
- La passerelle `mika-gateway`, qui sert le mode hébergé (Telegram, conteneurs par personne) : elle est déployée en image Docker, pas en binaire.
