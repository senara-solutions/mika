# Plan: Gentoo ebuild in Senara overlay (mika#624)

**Issue:** mika#624 — feat(ci): Gentoo ebuild in Senara overlay
**Milestone:** Distribution channels
**Target repo:** `senara-solutions/senara-overlay` (new Gentoo overlay repo)
**Dogfood target:** Vincent's Gentoo desktop

## Context

Mika currently ships via `make deploy` (local build + install to `~/.local/bin/`), Docker images, and a Debian packaging skeleton. Vincent's primary dev machine runs Gentoo Linux. A proper Gentoo ebuild in a dedicated overlay enables `emerge mika` for source-based installation with Portage integration — service management, dependency tracking, USE flags, and clean upgrades.

The Makefile already uses OpenRC (`rc-service mika-server restart`) for local dev, confirming the runtime is OpenRC-native. However, only a systemd service file exists in `packaging/systemd/`. An OpenRC init script is needed.

## Scope

### In scope
1. Create `senara-solutions/senara-overlay` GitHub repo with proper Gentoo overlay structure
2. Write `app-misc/mika/mika-0.12.2.ebuild` — source-based Rust build with `telemetry` USE flag
3. Write OpenRC init script for `mika-server`
4. Write OpenRC conf.d file for environment configuration
5. Add `pkg_postinst` that handles service restart on upgrade
6. CI workflow in the overlay repo to validate ebuild syntax (repoman/pkgcheck)

### Out of scope
- `mika-gateway` ebuild (requires Postgres, separate packaging concern)
- Binary package distribution (BINHOST)
- Multi-arch cross-compilation in ebuild
- Automated version bumps from mika release workflow (future enhancement)

## Implementation

### Step 1 — Create the overlay repository

Create `senara-solutions/senara-overlay` with Gentoo overlay structure:

```
senara-overlay/
├── metadata/
│   ├── layout.conf          # repo-name = senara, masters = gentoo
│   └── repo.json            # overlay metadata for eselect-repository
├── profiles/
│   └── repo_name            # "senara"
├── app-misc/
│   └── mika/
│       ├── metadata.xml     # package metadata (upstream, maintainer, USE flags)
│       ├── mika-0.12.2.ebuild
│       └── Manifest         # generated by ebuild digest
├── acct-user/
│   └── mika/
│       └── mika-0.ebuild    # system user (UID allocation via acct-user eclass)
├── acct-group/
│   └── mika/
│       └── mika-0.ebuild    # system group (GID allocation via acct-group eclass)
└── README.md
```

**Key files:**

`metadata/layout.conf`:
```
masters = gentoo
repo-name = senara
thin-manifests = true
sign-manifests = false
```

### Step 2 — acct-user/mika and acct-group/mika ebuilds

Per Gentoo policy, system users/groups are managed via `acct-user` and `acct-group` eclasses:

`acct-group/mika/mika-0.ebuild`:
```bash
EAPI=8
inherit acct-group
ACCT_GROUP_ID=-1  # dynamic allocation
```

`acct-user/mika/mika-0.ebuild`:
```bash
EAPI=8
inherit acct-user
ACCT_USER_ID=-1
ACCT_USER_GROUPS=( mika )
ACCT_USER_HOME=/var/lib/mika
ACCT_USER_SHELL=/sbin/nologin
```

### Step 3 — The mika ebuild

`app-misc/mika/mika-0.12.2.ebuild`:

```bash
EAPI=8
inherit cargo

DESCRIPTION="AI executive assistant with persistent memory"
HOMEPAGE="https://github.com/senara-solutions/mika"
SRC_URI="https://github.com/senara-solutions/mika/archive/v${PV}.tar.gz -> ${P}.tar.gz"

LICENSE="MIT"
SLOT="0"
KEYWORDS="~amd64"
IUSE="+telemetry"

RDEPEND="
    acct-user/mika
    acct-group/mika
    app-misc/jq
"
BDEPEND="
    virtual/rust
    virtual/pkgconfig
"
# Note: No dev-db/sqlite needed — rusqlite bundles SQLite
# Note: No dev-libs/openssl needed — all TLS via rustls

ECARGO_WORKSPACE=1
```

**Build phase:**
- `src_configure`: set cargo features based on USE flags (`telemetry` → `--features telemetry`)
- `src_compile`: `cargo build --release --workspace` with appropriate features
- `src_install`:
  - Install `mika` and `mika-server` binaries to `/usr/bin/`
  - Install OpenRC init script to `/etc/init.d/mika-server`
  - Install conf.d file to `/etc/conf.d/mika-server`
  - `keepdir /var/lib/mika /var/log/mika /etc/mika`
  - `fowners mika:mika /var/lib/mika /var/log/mika`
  - `fperms 0750 /etc/mika`
- `pkg_postinst`: print einfo about configuration, restart notice

**Dashboard handling:** The dashboard requires Node.js to build. Two options:
- **Option A (recommended):** Skip dashboard embedding in the ebuild. The CLI (`mika`) works without it; `mika-server` runs without the dashboard (API-only mode). Dashboard can be served separately or added later.
- **Option B:** Add `net-libs/nodejs` as BDEPEND with a `dashboard` USE flag. Adds significant build complexity.

Recommend Option A for the initial ebuild — keep it simple, dashboard is an enhancement.

### Step 4 — OpenRC init script

`files/mika-server.initd`:
```bash
#!/sbin/openrc-run

name="Mika AI Agent Server"
description="Mika AI executive assistant HTTP server"
command="/usr/bin/mika-server"
command_user="mika:mika"
command_background=true
pidfile="/run/${RC_SVCNAME}.pid"
directory="/var/lib/mika"

depend() {
    need net
    after dns
}

start_pre() {
    checkpath -d -m 0755 -o mika:mika /var/lib/mika
    checkpath -d -m 0755 -o mika:mika /var/log/mika
    checkpath -d -m 0750 -o mika:mika /etc/mika
}
```

`files/mika-server.confd`:
```bash
# Environment for mika-server
# See https://github.com/senara-solutions/mika for configuration docs

# Uncomment and set your API key
#MIKA_ANTHROPIC_API_KEY=""

# Log settings
MIKA_HOME="/var/lib/mika"
MIKA_LOG_FORMAT="json"
MIKA_SERVER_LOG_FILE="/var/log/mika/server.log"

# Optional: environment file with secrets
# MIKA_ENV_FILE="/etc/mika/mika-server.env"
```

### Step 5 — metadata.xml

```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE pkgmetadata SYSTEM "https://www.gentoo.org/dtd/metadata.dtd">
<pkgmetadata>
    <maintainer type="project">
        <email>dev@senara.solutions</email>
        <name>Senara Solutions</name>
    </maintainer>
    <upstream>
        <remote-id type="github">senara-solutions/mika</remote-id>
    </upstream>
    <use>
        <flag name="telemetry">Enable OpenTelemetry trace export (OTLP/Langfuse)</flag>
    </use>
</pkgmetadata>
```

### Step 6 — CI validation (overlay repo)

Add `.github/workflows/ci.yml` to `senara-overlay` that runs `pkgcheck scan` on PR to validate ebuild syntax, dependency declarations, and metadata.

### Step 7 — Installation instructions

Update `mika/docs/` or the overlay README with:

```bash
# Add the overlay
eselect repository add senara git https://github.com/senara-solutions/senara-overlay.git
emaint sync -r senara

# Install mika
emerge -av app-misc/mika

# Configure
nano /etc/mika/mika-server.env  # API keys

# Start
rc-service mika-server start
rc-update add mika-server default
```

## Risks and mitigations

| Risk | Mitigation |
|------|-----------|
| Cargo ebuild eclass may not handle workspace builds | Test with `ECARGO_WORKSPACE=1`; fall back to manual `cargo build` in `src_compile` if needed |
| Rust MSRV (1.91) newer than Gentoo stable toolchain | Use `~amd64` keywords (testing); Gentoo stable Rust updates quickly |
| Dashboard not embedded | CLI and API work fully without it; document as known limitation |
| Large compile time on first install | Expected for source-based distro; binary cache (BINHOST) is future scope |
