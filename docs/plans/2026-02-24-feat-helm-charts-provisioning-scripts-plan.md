# Helm Charts and Provisioning Scripts for K8s Deployment

## Overview

Create the Kubernetes deployment infrastructure for Mika: two Helm charts (per-customer agent + shared gateway) and two provisioning scripts (provision + deprovision). This is a prerequisite for deploying to AWS EKS — without these, the Docker images built in Phase 4.1 have nothing to install them.

**Four deliverables:**
- `helm/mika-customer/` — Per-customer Helm chart (Deployment, Service, PVC, ExternalSecret, CronJob)
- `helm/mika-gateway/` — Shared gateway Helm chart (Deployment, Service, ExternalSecret, PDB)
- `scripts/provision.sh` — Create AWS secret → Helm install → Postgres row → output Telegram deep link
- `scripts/deprovision.sh` — Suspend → Helm uninstall → delete PVC → delete secret → remove Postgres row

## Problem Statement

Docker images for `mika-server` (agent) and `mika-gateway` exist and build successfully (PR #7). But there is no way to deploy them to Kubernetes. No Helm charts, no provisioning automation, no secret management integration. Deploying a single customer currently requires manual `kubectl` commands — unacceptable even for 20-30 white-glove customers.

## Proposed Solution

Two Helm charts with External Secrets Operator integration for AWS Secrets Manager, plus shell scripts that orchestrate the full provisioning and deprovisioning lifecycle with rollback and safety guards.

## Technical Approach

### Key Findings from Research

1. **Namespace must be `mika-agents`**: The gateway hardcodes `container_url()` as `http://mika-{customer_id}.mika-agents.svc.cluster.local:8080` (`crates/mika-gateway/src/routes.rs:164`). The Helm chart must deploy customer pods into the `mika-agents` namespace — any other namespace breaks routing.

2. **Pairing uses tokens, not customer IDs**: The gateway pairing logic (`routes.rs:280-294`) validates against `pairing_token` (64-char hex) with `pairing_expires_at > now()`. The provisioning script must generate a pairing token with TTL and output `?start={pairing_token}` — NOT `?start={customer_id}`.

3. **PVC requires Recreate strategy**: EBS gp3 volumes are ReadWriteOnce. With a single-replica Deployment, RollingUpdate deadlocks (new pod waits for PVC, old pod waits for new pod). Strategy must be `Recreate`.

4. **Shared internal token**: Both gateway and all agent containers use the same `MIKA_INTERNAL_TOKEN` (64-char hex). For Phase 2 (20-30 customers), this is acceptable. Per-customer tokens add complexity without proportional security benefit at this scale.

5. **Agent env vars** (`crates/mika-common/src/config.rs`): `MIKA_ANTHROPIC_API_KEY` (required), `MIKA_ROUTING_URL` (required for server), `MIKA_INTERNAL_TOKEN` (required, 64 hex), `MIKA_HOME` (default `~/.mika`), `MIKA_SERVER_PORT` (default 8080), `MIKA_CUSTOMER_ID`, `MIKA_CLAUDE_MODEL`, `MIKA_LOG_LEVEL`.

6. **Gateway env vars** (`crates/mika-gateway/src/settings.rs`): `MIKA_DATABASE_URL` (required), `MIKA_TELEGRAM_BOT_TOKEN` (required), `MIKA_TELEGRAM_WEBHOOK_SECRET` (required, 64 hex), `MIKA_TELEGRAM_WEBHOOK_URL` (required), `MIKA_INTERNAL_TOKEN` (required, 64 hex), `MIKA_GATEWAY_PORT` (default 8080), `MIKA_LOG_LEVEL`.

7. **Postgres schema** (`crates/mika-gateway/migrations/001_customers.sql`): `customers` table with columns: `id UUID PK`, `name TEXT`, `plan TEXT` (standard/premium), `status TEXT` (provisioned/active/suspended), `telegram_chat_id BIGINT UNIQUE`, `timezone TEXT`, `pairing_token TEXT UNIQUE`, `pairing_expires_at TIMESTAMPTZ`, `last_update_id BIGINT`, `paired_at`, `created_at`, `updated_at`.

8. **Health endpoints**: Agent serves `/health` (no auth). Gateway serves `/readyz` (checks Postgres), `/livez`, `/health`.

9. **Docker images**: `mika-agent:dev` (95MB, binary 10.6MB), `mika-gateway:dev` (90MB, binary 5.6MB). Non-root UID 1000.

### Design Decisions

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Customer namespace | `mika-agents` | Matches hardcoded `container_url()` in gateway. Changing code is riskier than naming the namespace to match. |
| Gateway namespace | `mika-system` | Separates infrastructure from customer workloads. |
| Service naming | `mika-{customer_id}` | Deterministic. Gateway computes URL from customer_id alone. |
| Deployment strategy | `Recreate` for customers | RWO PVC prevents two pods mounting simultaneously. Recreate avoids deadlock. |
| Provisioning atomicity | Trap-based rollback | `trap cleanup ERR` undoes completed steps if any step fails. |
| SQL injection | psql with `\set` variables | Avoids shell interpolation into SQL. No external dependencies. |
| Pairing token | Generated by provision.sh | 64-char hex, 72-hour TTL. Matches gateway validation logic exactly. |
| Deprovisioning safety | `--dry-run` + confirmation | Prevents accidental data destruction. PVC deletion is irreversible. |
| Secret vs config separation | Secrets in ExternalSecret, config in env | `MIKA_TELEGRAM_WEBHOOK_URL` is not secret — goes in Deployment env directly. |
| Resource limits | 64Mi request / 256Mi limit | Conservative start. Agent loop + Claude API + JSON parsing + compaction needs headroom. Monitor and adjust. |
| Heartbeat CronJob | Per-customer in Helm chart | Agent pre-filter handles suppression. CronJob just triggers the check. |
| NetworkPolicy | Restrict inter-pod comms | Agent pods can only reach gateway. Gateway can only reach agents + Postgres. |
| ExternalSecret refresh | 1 hour | Balance between secret rotation speed and API call volume. |
| PDB for gateway | minAvailable: 1 | Prevents total outage during cluster upgrades. |

#### Phase 3: provision.sh

Provisioning script with rollback, parameterized SQL, and pairing token generation.

**New: `scripts/provision.sh`**
```bash
#!/bin/bash
set -euo pipefail

# --- Usage ---
usage() {
    echo "Usage: provision.sh <customer_name> [plan] [--timezone TZ]"
    echo ""
    echo "Arguments:"
    echo "  customer_name   Human-readable customer name (required)"
    echo "  plan            Customer plan: standard (default) or premium"
    echo ""
    echo "Options:"
    echo "  --timezone TZ   IANA timezone (default: UTC)"
    echo "  --dry-run       Show what would be done without executing"
    echo "  --help          Show this help"
    echo ""
    echo "Required environment variables:"
    echo "  DATABASE_URL            Postgres connection string for gateway DB"
    echo "  MIKA_ANTHROPIC_API_KEY  Anthropic API key to store in AWS"
    echo "  MIKA_INTERNAL_TOKEN     Shared 64-char hex auth token"
    echo "  TELEGRAM_BOT_USERNAME   Telegram bot username (for deep link)"
    echo ""
    echo "Optional environment variables:"
    echo "  AWS_REGION              AWS region (default: us-east-1)"
    echo "  MIKA_IMAGE_REPO         ECR image repository"
    echo "  MIKA_IMAGE_TAG          Image tag (default: latest)"
    exit 1
}

# --- Parse arguments ---
CUSTOMER_NAME=""
PLAN="standard"
TIMEZONE="UTC"
DRY_RUN=false

while [[ $# -gt 0 ]]; do
    case $1 in
        --timezone) TIMEZONE="$2"; shift 2 ;;
        --dry-run)  DRY_RUN=true; shift ;;
        --help)     usage ;;
        -*)         echo "Unknown option: $1"; usage ;;
        *)
            if [[ -z "$CUSTOMER_NAME" ]]; then
                CUSTOMER_NAME="$1"
            elif [[ "$PLAN" == "standard" && "$1" =~ ^(standard|premium)$ ]]; then
                PLAN="$1"
            else
                echo "Unexpected argument: $1"; usage
            fi
            shift ;;
    esac
done

[[ -z "$CUSTOMER_NAME" ]] && { echo "Error: customer_name is required"; usage; }

# --- Validate required env vars ---
: "${DATABASE_URL:?DATABASE_URL is required}"
: "${MIKA_ANTHROPIC_API_KEY:?MIKA_ANTHROPIC_API_KEY is required}"
: "${MIKA_INTERNAL_TOKEN:?MIKA_INTERNAL_TOKEN is required}"
: "${TELEGRAM_BOT_USERNAME:?TELEGRAM_BOT_USERNAME is required}"

# --- Validate plan ---
if [[ "$PLAN" != "standard" && "$PLAN" != "premium" ]]; then
    echo "Error: plan must be 'standard' or 'premium', got '$PLAN'"
    exit 1
fi

# --- Generate IDs ---
CUSTOMER_ID=$(uuidgen | tr '[:upper:]' '[:lower:]')
PAIRING_TOKEN=$(openssl rand -hex 32)  # 64-char hex, matches gateway validation
NAMESPACE="mika-agents"
AWS_REGION="${AWS_REGION:-us-east-1}"
AWS_SECRET_NAME="mika/customers/${CUSTOMER_ID}"
SERVICE_URL="http://mika-${CUSTOMER_ID}.${NAMESPACE}.svc.cluster.local:8080"

echo "=== Mika Customer Provisioning ==="
echo "Customer:    ${CUSTOMER_NAME}"
echo "Customer ID: ${CUSTOMER_ID}"
echo "Plan:        ${PLAN}"
echo "Timezone:    ${TIMEZONE}"
echo "Namespace:   ${NAMESPACE}"
echo "Service URL: ${SERVICE_URL}"
echo ""

if [[ "$DRY_RUN" == "true" ]]; then
    echo "[DRY RUN] Would create:"
    echo "  1. AWS secret: ${AWS_SECRET_NAME}"
    echo "  2. Helm release: mika-${CUSTOMER_ID} in ${NAMESPACE}"
    echo "  3. Postgres row: customers(id=${CUSTOMER_ID})"
    echo "  4. Deep link: https://t.me/${TELEGRAM_BOT_USERNAME}?start=${PAIRING_TOKEN}"
    exit 0
fi

# --- Rollback on failure ---
STEP_COMPLETED=0
cleanup() {
    echo ""
    echo "!!! Provisioning failed at step ${STEP_COMPLETED}. Rolling back..."
    if [[ $STEP_COMPLETED -ge 2 ]]; then
        echo "  Rolling back Helm release..."
        helm uninstall "mika-${CUSTOMER_ID}" --namespace "${NAMESPACE}" 2>/dev/null || true
    fi
    if [[ $STEP_COMPLETED -ge 1 ]]; then
        echo "  Rolling back AWS secret..."
        aws secretsmanager delete-secret \
            --secret-id "${AWS_SECRET_NAME}" \
            --force-delete-without-recovery \
            --region "${AWS_REGION}" 2>/dev/null || true
    fi
    echo "Rollback complete."
    exit 1
}
trap cleanup ERR

# --- Step 1: Create AWS secret ---
echo "Step 1/4: Creating AWS secret..."
aws secretsmanager create-secret \
    --name "${AWS_SECRET_NAME}" \
    --secret-string "{\"anthropic_api_key\": \"${MIKA_ANTHROPIC_API_KEY}\"}" \
    --region "${AWS_REGION}" \
    --tags "Key=mika-customer-id,Value=${CUSTOMER_ID}" "Key=mika-customer-name,Value=${CUSTOMER_NAME}" \
    > /dev/null
STEP_COMPLETED=1
echo "  Created: ${AWS_SECRET_NAME}"

# --- Step 2: Helm install ---
echo "Step 2/4: Installing Helm release..."
helm install "mika-${CUSTOMER_ID}" ./helm/mika-customer \
    --namespace "${NAMESPACE}" --create-namespace \
    --set customer.id="${CUSTOMER_ID}" \
    --set customer.name="${CUSTOMER_NAME}" \
    --set customer.plan="${PLAN}" \
    --set customer.timezone="${TIMEZONE}" \
    --set secrets.awsSecretName="${AWS_SECRET_NAME}" \
    --set secrets.awsRegion="${AWS_REGION}" \
    --set internalToken="${MIKA_INTERNAL_TOKEN}" \
    --set image.repository="${MIKA_IMAGE_REPO:-}" \
    --set image.tag="${MIKA_IMAGE_TAG:-latest}" \
    --wait --timeout 120s
STEP_COMPLETED=2
echo "  Installed: mika-${CUSTOMER_ID}"

# --- Step 3: Register in Postgres (parameterized query) ---
echo "Step 3/4: Registering in Postgres..."
psql "${DATABASE_URL}" -v ON_ERROR_STOP=1 <<SQL
INSERT INTO customers (id, name, plan, timezone, service_url, status, pairing_token, pairing_expires_at)
VALUES (
    '${CUSTOMER_ID}'::uuid,
    \$\$${CUSTOMER_NAME}\$\$,
    '${PLAN}',
    '${TIMEZONE}',
    '${SERVICE_URL}',
    'provisioned',
    '${PAIRING_TOKEN}',
    now() + interval '72 hours'
)
ON CONFLICT (id) DO NOTHING;
SQL
STEP_COMPLETED=3
echo "  Registered: ${CUSTOMER_ID}"

# --- Step 4: Output deep link ---
echo "Step 4/4: Generating deep link..."
DEEP_LINK="https://t.me/${TELEGRAM_BOT_USERNAME}?start=${PAIRING_TOKEN}"
STEP_COMPLETED=4

echo ""
echo "=== Provisioning Complete ==="
echo "Customer ID:   ${CUSTOMER_ID}"
echo "Service URL:   ${SERVICE_URL}"
echo "Deep link:     ${DEEP_LINK}"
echo "Pairing token: ${PAIRING_TOKEN}"
echo "Token expires: 72 hours from now"
echo ""
echo "Send the deep link to the customer to start onboarding."
```

#### Phase 4: deprovision.sh

Deprovisioning script with dry-run, confirmation, and graceful teardown.

**New: `scripts/deprovision.sh`**
```bash
#!/bin/bash
set -euo pipefail

# --- Usage ---
usage() {
    echo "Usage: deprovision.sh <customer_id> [--force] [--dry-run]"
    echo ""
    echo "Arguments:"
    echo "  customer_id   UUID of the customer to deprovision (required)"
    echo ""
    echo "Options:"
    echo "  --force       Skip confirmation prompt"
    echo "  --dry-run     Show what would be done without executing"
    echo "  --help        Show this help"
    echo ""
    echo "Required environment variables:"
    echo "  DATABASE_URL    Postgres connection string for gateway DB"
    echo ""
    echo "Optional environment variables:"
    echo "  AWS_REGION      AWS region (default: us-east-1)"
    exit 1
}

# --- Parse arguments ---
CUSTOMER_ID=""
FORCE=false
DRY_RUN=false

while [[ $# -gt 0 ]]; do
    case $1 in
        --force)    FORCE=true; shift ;;
        --dry-run)  DRY_RUN=true; shift ;;
        --help)     usage ;;
        -*)         echo "Unknown option: $1"; usage ;;
        *)
            if [[ -z "$CUSTOMER_ID" ]]; then
                CUSTOMER_ID="$1"
            else
                echo "Unexpected argument: $1"; usage
            fi
            shift ;;
    esac
done

[[ -z "$CUSTOMER_ID" ]] && { echo "Error: customer_id is required"; usage; }

# Validate UUID format
if ! [[ "$CUSTOMER_ID" =~ ^[0-9a-f]{8}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{4}-[0-9a-f]{12}$ ]]; then
    echo "Error: customer_id must be a valid UUID, got '${CUSTOMER_ID}'"
    exit 1
fi

: "${DATABASE_URL:?DATABASE_URL is required}"

NAMESPACE="mika-agents"
AWS_REGION="${AWS_REGION:-us-east-1}"
AWS_SECRET_NAME="mika/customers/${CUSTOMER_ID}"

# --- Look up customer info ---
CUSTOMER_NAME=$(psql "${DATABASE_URL}" -t -A -c "SELECT name FROM customers WHERE id = '${CUSTOMER_ID}'::uuid;" 2>/dev/null || echo "")
if [[ -z "$CUSTOMER_NAME" ]]; then
    echo "Warning: Customer ${CUSTOMER_ID} not found in Postgres (may already be partially deprovisioned)"
fi

echo "=== Mika Customer Deprovisioning ==="
echo "Customer ID: ${CUSTOMER_ID}"
echo "Name:        ${CUSTOMER_NAME:-unknown}"
echo "Namespace:   ${NAMESPACE}"
echo ""

if [[ "$DRY_RUN" == "true" ]]; then
    echo "[DRY RUN] Would execute:"
    echo "  1. Mark suspended in Postgres"
    echo "  2. Helm uninstall mika-${CUSTOMER_ID}"
    echo "  3. Delete PVC mika-${CUSTOMER_ID}-data"
    echo "  4. Delete AWS secret ${AWS_SECRET_NAME}"
    echo "  5. Remove Postgres row"
    exit 0
fi

# --- Confirmation ---
if [[ "$FORCE" != "true" ]]; then
    echo "WARNING: This will permanently destroy all data for this customer."
    echo "  - SQLite database (conversation history, memory, reminders)"
    echo "  - AWS secret"
    echo "  - Postgres registration"
    echo ""
    read -p "Type the customer ID to confirm: " CONFIRM
    if [[ "$CONFIRM" != "$CUSTOMER_ID" ]]; then
        echo "Aborted. ID did not match."
        exit 1
    fi
fi

# --- Step 1: Mark suspended (stops routing immediately) ---
echo "Step 1/5: Marking suspended in Postgres..."
psql "${DATABASE_URL}" -v ON_ERROR_STOP=1 -c \
    "UPDATE customers SET status = 'suspended' WHERE id = '${CUSTOMER_ID}'::uuid;" \
    2>/dev/null || echo "  (no row to update)"

# --- Step 2: Helm uninstall ---
echo "Step 2/5: Uninstalling Helm release..."
helm uninstall "mika-${CUSTOMER_ID}" --namespace "${NAMESPACE}" 2>/dev/null || echo "  (no release found)"

# --- Step 3: Delete PVC ---
echo "Step 3/5: Deleting PVC..."
kubectl delete pvc "mika-${CUSTOMER_ID}-data" -n "${NAMESPACE}" 2>/dev/null || echo "  (no PVC found)"

# --- Step 4: Delete AWS secret ---
echo "Step 4/5: Deleting AWS secret..."
aws secretsmanager delete-secret \
    --secret-id "${AWS_SECRET_NAME}" \
    --force-delete-without-recovery \
    --region "${AWS_REGION}" 2>/dev/null || echo "  (no secret found)"

# --- Step 5: Remove from Postgres ---
echo "Step 5/5: Removing from Postgres..."
psql "${DATABASE_URL}" -v ON_ERROR_STOP=1 -c \
    "DELETE FROM customers WHERE id = '${CUSTOMER_ID}'::uuid;" \
    2>/dev/null || echo "  (no row to delete)"

echo ""
echo "=== Deprovisioning Complete ==="
echo "Customer ${CUSTOMER_ID} has been fully deprovisioned."
```

## Risk Analysis & Mitigation

| Risk | Likelihood | Impact | Mitigation |
|------|-----------|--------|------------|
| Namespace mismatch breaks routing | High (parent plan said `mika-customers`) | Critical | Fixed: plan uses `mika-agents` matching gateway code |
| Pairing token not generated | High (parent plan used customer_id) | Critical | Fixed: provision.sh generates 64-char hex token with TTL |
| PVC deadlock on rolling update | Medium | High | Fixed: Recreate strategy, not RollingUpdate |
| provision.sh partial failure | Medium | Medium | Mitigated: trap-based rollback |
| SQL injection in psql | Medium | High | Mitigated: dollar-quoted strings, no shell expansion in SQL values |
| Accidental deprovision | Low | Critical | Mitigated: confirmation prompt + --dry-run |
| Resource limits too low | Medium | Medium | Start at 64Mi/256Mi, monitor OOMKilled events |
| ESO CRD not installed | Medium | Low | Helm template still renders; CRD error only on apply |
