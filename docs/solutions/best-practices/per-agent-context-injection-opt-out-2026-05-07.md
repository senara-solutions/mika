# Per-Agent Context Injection Opt-Out via `[context.summary].inject`

## Context

mika#1009 identified that mika-arch's conversational summary — generated by compaction from prior conversation turns — was leaking operational detail into the architect agent's system prompt. The summary contained dispatch decisions, error discussions, and implementation mechanics that contaminated the architect's reasoning, causing it to produce plans influenced by irrelevant operational context.

The 4-axis fix plan identified Axis 4 (per-agent summary opt-out) as the smallest first ship. The key insight: the protection must be **load-prevention**, not merely injection-prevention. If the summary is loaded from the DB but conditionally skipped during `push_str`, a future refactor could accidentally reference the loaded value elsewhere in the function, re-introducing the leak.

## Guidance

### Nested section design for extensibility

Use `[context.summary]` (nested) rather than `[context] inject_summary` (flat). This pre-empts renaming when sibling fields are added (e.g., Axis 3's `budget_tokens`):

```toml
[context.summary]
inject = false
# Future Axis 3:
# budget_tokens = 8000
```

### Load-prevention gate pattern

Gate the `db.load_conversation_summary()` call itself, not just the `push_str` calls. The outer `if` ensures the summary is never deserialized into the turn's scope:

```rust
// Load-prevention gate: when [context.summary].inject is false, skip the
// db.load_conversation_summary() call entirely (mika#1009 leak protection).
#[allow(clippy::collapsible_if)]
if ctx.identity.context.summary.inject {
    if let Some(summary) = db.load_conversation_summary().await? {
        system.push_str("\n## Conversation Summary\n");
        // ...
    }
}
```

The `#[allow(clippy::collapsible_if)]` is intentional — collapsing the nested `if` would obscure the load-prevention contract.

### Fail-closed identity must mirror the opt-out

When a well-known agent's `identity.toml` is malformed, `fail_closed_identity()` constructs a neutered identity. This must explicitly set `inject: false` — using `ContextIdentityConfig::default()` (which defaults to `true`) would silently re-enable the leak the feature is meant to prevent.

### Gate both injection sites symmetrically

Both the conversation-mode site (`run_agent_inner`) and the silent-mode site (`run_silent_inner`) must be gated. Even if an agent currently doesn't use silent-mode triggers, gating both prevents asymmetry confusion and pre-empts the gap if the agent acquires a silent-mode trigger in the future.

## Why This Matters

Context-channel leakage is a class of prompt contamination where data intended for one context (operational dispatch) bleeds into another (architectural reasoning). The load-prevention gate is the structural defense: by ensuring the summary is never even loaded from the DB when the flag is false, no downstream code path — logging, audit dumps, conditional re-injection — can accidentally access it.

Without the nested-section design, adding Axis 3's `budget_tokens` would require a field rename, config migration, and documentation update across all agents using the flat-field shape.

## When to Apply

- Adding new per-agent prompt-assembly toggles: follow the `[context.<block>]` nested pattern
- Disabling summary injection for a new well-known agent: set `[context.summary] inject = false` in the agent's identity.toml
- Adding new context blocks (future: tools, system, memory): create sibling subsections under `[context]`
- Reviewing fail-closed identity: ensure any security-relevant config flags are explicitly set, not left to defaults

## Examples

**Opting a well-known agent out (in `well_known_agents.rs`):**

```rust
// In the build_mika_arch_identity format string:
[context.summary]
inject = false
```

**Preserving default behavior (existing agents):**

No change needed. Existing `identity.toml` files without `[context]` parse with `inject = true` via `#[serde(default)]` at both the top-level `context` field and the nested `summary` field.

**Fail-closed identity construction:**

```rust
context: ContextIdentityConfig {
    summary: ContextSummaryConfig { inject: false },
},
```
