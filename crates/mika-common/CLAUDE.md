# mika-common — Shared Library

Shared library used by all Mika crates: config, LLM providers, Claude API client, OAuth, GitHub App auth, logging, telemetry, home directory, and test utilities.

## Modules

- **Config:** config-rs with `MIKA_` prefix, `ConfigKeyInfo` registry with `ConfigBackend` enum, `get_effective_value`/`lookup_config_key` helpers. All API keys and tokens in `Settings` use `secrecy::SecretString` for compile-time exposure safety and zeroize-on-drop. Secrets exposed at accessor boundary via `.expose_secret()`. `get_effective_value()` returns `"[SET]"` for secret-flagged fields.
- **Validation:** `validation.rs` — API key format, file permissions, binary-in-PATH, config value validation
- **Dotenv:** `~/.mika/.env` load/read/write via dotenvy, `parse_dotenv` for reading without env mutation, `dotenv_to_toml` for config-rs injection
- **Claude API client:** Typed request/response, retry, prompt caching injection
- **OAuth:** PKCE token exchange (`oauth.rs` — PKCE flow, `OAuthTokenManager` with `tokio::sync::RwLock` caching, `~/.mika/oauth.json` persistence)
- **GitHub App auth:** `github_app.rs` — RS256 JWT signing, installation token exchange and caching with `tokio::sync::RwLock` double-checked locking, `GitHubApp::from_settings()` constructor (takes `&Settings`), `GitHubApp::from_credentials()` constructor (takes raw `app_id`, `private_key_b64`, `installation_id` — used by the gateway which has its own settings type), file-based token cache at `{home_dir}/github_app_token.json` for short-lived CLI processes via `installation_token_with_file_cache()` — per-agent when `--agent` flag resolves to agent home dir
- **Logging:** tracing + tracing-subscriber setup
- **Telemetry:** Feature-gated OTel export. See `crates/mika-agent/CLAUDE.md` for observability architecture.
- **Text:** `text.rs` — `safe_truncate(s, max_bytes)` for UTF-8-safe byte-budget truncation using `floor_char_boundary`. Returns `&str`, never panics on multi-byte characters. Use for log line widths, prompt size budgets, and error message previews. Distinct from `db::truncate_chars` (char-count-based, appends "...", returns `String`).

  **Typographic normalisation (mika#2247).** `normalize_typography(String) -> String` rewrites em-dashes (U+2014), en-dashes (U+2013) and ellipses (U+2026) into plain ASCII punctuation, by three ordered rules: line-leading → `-` (list or dialogue dash); whitespace on both sides → `,`, or nothing when the clause already closed with `,;:.!?` (French apposition); no adjacent whitespace → `-` (range). **A substitution and not an EndTurn guard, and that is the arbitration of the whole axis:** the mika#953 family holds a budget of one re-prompt, so against a model that emits em-dashes *by style* a guard would fire every turn, spend its budget and let the character through anyway — the literal shape mika#2368 had to rattraper with an engine net. An em-dash is also not a false assertion needing rewriting: it is a rendering defect whose correct repair is mechanical and meaning-preserving, cannot fail, and costs no LLM call. **Idempotent by absence rather than by fixpoint** (the output carries none of the three code points) and **UTF-8 safe by iterating over `char`** — a byte-slicing version would panic mid-character and `scripts/check-byte-slices.sh` would refuse it. Named cost: it does not tell prose from a fenced code block; the family tier emits no code (its persona forbids technical vocabulary), so the population is empty and a fence parser would be machinery for nobody.

  `normalize_typography_for_persona(String, PersonaProfile)` is the **single site of the persona crossing** — an exhaustive `match` with no `_ =>` arm (model: `prompt::hosting_ground_truth_line`, mika#2290), so a new persona is forced to decide instead of inheriting. `Operator` is deliberately untouched: careful typography is the register Vincent chose for himself, and mika#2247's acceptance criterion names the general-public tenant. The three consumers live in `mika-agent` and compose it with `strip_internal_tags` at the EndTurn extraction, the continuation turn and the `send_message` tool; `agent_loop::tests::mika2247_every_output_site_normalises_its_typography` is a source scan that refuses a fourth, un-normalised site — **with no allowlist**, so a fourth one is halt-and-surface.

  Note the companion half in `home.rs`: `FAMILY_SOUL` itself carried nine U+2014, one of them inside the `## First-turn opening` section the model reproduces at every tenant's first turn — so the persona did not merely fail to forbid the character, it **prescribed** it through an approved example. The constant is now ASCII-only, pinned by `mika2247_family_soul_carries_no_em_dash` and `mika2247_family_soul_marker_is_intact` (the second because the rewrite must not disturb the mika#1962 provisioning sentinel on the last line).
- **Home directory:** Resolution utilities. `bootstrap_fresh_install` writes the default agent's `identity.toml` from `DEFAULT_IDENTITY`, which ships a narrow `[skills].allowlist` (`DEFAULT_AGENT_SKILL_ALLOWLIST`). A missing/empty allowlist is default-permissive and leaks internal `Disposition:` contracts from engineering skills into user-facing replies (mika#1596); keep the constant and the `DEFAULT_IDENTITY` TOML array in sync (asserted by `home.rs` tests). **Family tier (mika#1778), champion tier + two-axis split (mika#2023):** `bootstrap()` reads `AgentTier::from_env()` (`MIKA_AGENT_TIER` env var; recognized `"default"`/`"family"`/`"champion"`, case-insensitive, trimmed) and picks the templates through **two independent axes** rather than one match written twice: `identity_toml()` reads `tools_profile()` (`ToolsProfile::Operator|Family`), `soul_md()` reads `persona_profile()` (`PersonaProfile::Operator|Family`). `Champion` = family tools + the placeholder persona `CHAMPION_PERSONA_PLACEHOLDER` — one named constant, the single site to change when the champion's voice is decided. `AgentTier::skill_allowlist()` exposes the tools surface directly, and `expects_family_provisioning()` answers "does this tier write the family templates?" through an exhaustive match — that method exists because `mika-agent`'s tier guard used to ask it with `tier == AgentTier::Family`, an equality the compiler cannot see through. A **non-empty unrecognized** value fails closed to the most restricted tools tier (`Family`) with the `warn!` naming it; absence, `""` and `"default"` stay `Default`, because an unset variable is the legitimate operator workstation, not a misconfiguration. The family variant carries the Vincent-approved French persona for non-technical family members; its allowlist is `FAMILY_AGENT_SKILL_ALLOWLIST` (calendar/google-workspace/file-reader/web-search/desktop/browser-control) — explicitly excludes dev/orchestrator surfaces. The env-var-in-sync-with-TOML-array test guard applies to the family variant too. **Provisioning detection (mika#1962):** `FAMILY_SOUL` now **ends** with the `FAMILY_SOUL_MARKER` sentinel (`<!-- MIKA_FAMILY_SOUL_MARKER -->`, an HTML comment so it carries no instruction into the system prompt). It is a **tail** marker deliberately: `build_compact_system_prompt` in `mika-agent` uses `soul_content.lines().next()` as the entire `## Personality` section on the MikaModel path, so a leading sentinel would replace the family persona with a platform-internal comment on exactly the tier the marker protects. `home::tests::family_soul_marker_is_not_the_persona_line` pins that invariant here, at the source, because mika-common cannot see that builder, and two helpers answer "is this agent family-provisioned?" for the boot-time tier guard in `mika-agent`: `soul_has_family_marker` (axis 1) and `identity_allowlist_matches_family` (axis 2, set comparison — order- and duplicate-insensitive). The marker is **not retroactive** — `write_default_if_missing` never rewrites an existing `soul.md`, so every family agent bootstrapped before mika#1962 has a marker-less soul and axis 2 is the load-bearing detector for the installed base. Both helpers return `Ok(false)` for an absent file and `Err` for a present-but-unreadable one. Malformed TOML is narrower: `identity_allowlist_matches_family` errors only when the raw file still contains `FAMILY_AGENT_SKILL_ALLOWLIST` names, and otherwise returns `Ok(false)` with a `warn!` — a corrupted *family* identity must refuse startup, an unrelated typo in an *operator* identity must not down the process. See the workspace `CLAUDE.md` § `MIKA_AGENT_TIER`.
- **Model list cache:** `llm/models.rs` — `get_models()` fetches from provider `/models` API with 24h TTL file cache at `{agent_home}/cache/models/{provider}.json`, hardcoded lists for Anthropic/Google, `ModelCache`/`ModelInfo` types

## LLM Providers

Multi-provider via `LlmProvider` trait — 13 supported providers, each with its own `model`, `api_key`, and `base_url` fields in config. Active provider selected by `llm_provider` config key. Providers: Anthropic (default, Claude Sonnet 4.6), OpenAI, OpenRouter, Groq, Ollama, Mistral, Google (Gemini), DeepSeek, MiniMax, Kimi, Qwen, MikaModel, Z.AI (direct GLM API at `https://api.z.ai/api/paas/v4`, `zai_*` keys — bypasses OpenRouter margin for native GLM routing). Anthropic uses its native API client. Ollama and MikaModel both use the native Ollama provider (`llm/ollama.rs`) that targets `/api/chat` — no `/v1` suffix required in the base URL, supports tool calling natively (synthetic IDs since Ollama omits them), no vision support (deferred). MikaModel is a separate `ProviderKind` so the operator can configure the internal endpoint (`mikamodel_*` keys, defaults to `http://localhost:11434` + model `"mika"`) independently from a general-purpose Ollama (`ollama_*` keys); the same transport, different config namespace. All other non-Anthropic providers use the `OpenAiCompatibleProvider` adapter.

**Deadline-aware retry (#939, mika#2189):** `LlmProvider` exposes `send_message_with_deadline(request, deadline: Option<Instant>)` with a default implementation that ignores the deadline and delegates to `send_message`. Both `AnthropicProvider` and `OpenAiCompatibleProvider` override the method to check the remaining deadline budget before each retry — when remaining falls under the threshold, the retry chain aborts immediately with a "deadline budget insufficient" error context. Callers without deadline visibility pass `None` and get unchanged behavior. The agent loop (`crates/mika-agent/src/agent.rs`) is the primary caller with `Some(deadline)`.

Since mika#2189 the threshold is **derived from the effective per-call plafond**, not from literals: `LlmTimeoutBudget::typical_call_duration_secs()` (`0.75 ×`) `+ retry_buffer_secs()` (`0.25 ×`), and `transport_retry_min_remaining_secs()` (`0.50 ×`) for transport-class failures (mika#1744). `TYPICAL_CALL_DURATION_SECS = 90`, `RETRY_BUFFER_SECS = 30` and `TRANSPORT_RETRY_MIN_REMAINING_SECS = 60` survive as **pins for those fractions at the default plafond**, not as the live values — a literal calibrated on a 120 s plafond describes a geometry that stops existing the moment an operator raises it.

**Timeout budgets (mika#2189).** `llm/budget.rs` owns `LlmTimeoutBudget`, the pair `(per-call plafond, per-agent envelope)` from which those three thresholds and `max_attempts` are computed — so a budget cannot be half-configured. `validate()` refuses `plafond >= envelope` (a configuration where one call may consume the whole envelope leaves the agent loop nothing for a second step) and is called from `create_provider_with_budget`, the cold path where mika#1660's too-small-plafond panic already lives. Providers carry the budget they were built with and surface it via `LlmProvider::timeout_budget()` — the agent loop reads its deadline from **there** rather than from a constant of its own, which is what stops the plafond and the envelope drifting apart again. `from_env()` reads `MIKA_LLM_HTTP_TIMEOUT_SECS` and `MIKA_AGENT_TOTAL_TIMEOUT_SECS`; `Settings::llm_timeout_budget()` supplies the per-agent form (`llm_http_timeout_secs` / `agent_total_timeout_secs` in `config.toml`) and returns it **unvalidated on purpose** — validation belongs at provider construction, and a getter that validated would give the invariant two homes. `timeout_budget()`'s default impl re-reads the environment, which is right for mocks and for the Anthropic rail; note `claude.rs` still poses its own `120s` literal instead of reading the plafond — a real inconsistency, named as out of scope by mika#2189 rather than bundled into it.

**Declared worst case (mika#2342).** `LlmProvider::worst_case_failure_secs()` is
what the agent-loop watchdog is sized on (`agent_loop::run_loop`, see
`mika-agent/CLAUDE.md` § *LLM-call watchdog*). It is **asked of the rail**, not
derived from the budget, and the difference is load-bearing: the default returns
`timeout_budget().worst_case_failure_secs(DEFAULT_ATTEMPTS_HARD_CAP)`, which is
right for any rail whose transport honours the budget it was built with — but
`AnthropicProvider` **overrides** it, because `claude.rs` hands `reqwest` the
literal `ANTHROPIC_HTTP_TIMEOUT_SECS` (120) instead of reading the plafond. At
`MIN_HTTP_TIMEOUT_SECS` a derived value would answer 40 s for a transport that
can physically take 480, and a watchdog sized on that would cut healthy calls: a
guaranteed false positive. The override does not make `claude.rs` consistent —
that stays out of scope, named by mika#2189 — it converts a silent trap into a
declared value. `MAX_ATTEMPTS_HARD_CAP` moved from `openai.rs` to
`llm/mod.rs::DEFAULT_ATTEMPTS_HARD_CAP` in the same change: a default method on
the trait cannot read a constant private to one rail's module, and the move
removed two copies rather than adding a third.

`MockLlmProvider` is the one rail deliberately outside that population
(`llm::tests::mika2342_mock_is_excluded_from_the_declared_worst_case_population`):
it has no transport, so "the declared worst case covers the transport's real
worst case" has no referent for it — **no follow-up ticket, and that is stated
rather than implied**. It is also the one rail where the watchdog is the *first*
cancellation mechanism instead of the second, which is why the property is
phrased conditionally at the call site. The exception carries a self-cleaning
assertion: the day the mock gains a budget of its own, it goes red.

**Per-attempt instrumentation (mika#2342).** `llm_call started` is emitted once,
*before* the retry chain, and used to carry neither the chain's width nor the
request size — so N silent bounded attempts and one unbounded call read
identically. Each rail now emits `llm_call_attempt` immediately before
`send_once` with `attempt`, `max_attempts` and `request_bytes`, and `started`
carries `max_attempts` too. The Anthropic rail cannot measure the brief itself
(it only ever sees the converted `MessagesRequest`), so `AnthropicProvider`
threads `LlmRequest::payload_bytes()` down through
`ClaudeClient::send_message_with_deadline` — one measure for the three rails
rather than a second one free to disagree. When it is genuinely absent the event
says so via `request_bytes_measured`, instead of a `0` indistinguishable from an
empty request.

**Budget provenance (mika#2293).** `llm/budget_provenance.rs` answers the question mika#2189 shipped without: *which* plafond and envelope is this agent actually running under, and **through which door of the cascade**. mika-arch got `240/900` in its `config.toml` on 2026-09-06 and the 2026-09-11 measurement still saw cuts at 120 s exactly — the fleet default — with no line of log anywhere able to say what annulled it. `BudgetProvenance::resolve(global_home, agent_home)` reports, per key, a `BudgetSource` (`agent_dotenv` / `process_env` / `agent_config` / `global_config` / `default`), the raw string as written, and what it parses to; `log_llm_budget_resolved` emits the `llm_budget_resolved` INFO event from the two callers that already know the agent (`server::init_agent`, `teams::engine`) — **ungated** by `MIKA_STORE_LLM_CALLS`, because a configuration event has to stay readable exactly when telemetry was cut to reduce noise, and deduplicated on the resolved pair so a repetition is silent while a *change* is re-emitted.

The five sources split three remedies that nothing else separates: `agent_config` says the setting is in force and the cause is elsewhere; `process_env` says a fleet-wide variable is shadowing the per-agent file; `default` says the file was never read or never carried the key. `global_config` is split out of `agent_config` deliberately — the question is whether the *per-agent* setting took, and answering "per-agent" for a value from the shared `~/.mika/config.toml` would answer it wrongly.

**The model half (mika#2328).** The same event now carries `provider`, `provider_source`, `model`, `model_source` and `model_config_key`, resolved by `ModelProvenance` through the **same** `CascadeLayers` — one read of the four doors, two facts, because a cut turn is diagnosed with the model *and* the envelope. What it closes: `zai_model = "glm-5.2"` is the only model line `well_known_agents.rs` has ever declared for mika-qa, while the mika#2328 incident of 2026-09-15 was produced by a **glm-5.3** in service — an out-of-repo edit of the agent's `config.toml` that `reconcile_well_known_config` preserves while provisioning is frozen. `turn_usage` carries provider and model, but per turn, in 19 GB of log, with no provenance; what was missing was a *configuration* event. **The model key's NAME is derived from the provider in force** (`zai_model`, `openrouter_model`, …) rather than hard-coded — a fixed key would report `default` for a model that is perfectly well declared, i.e. a false provenance, which this module holds to be strictly worse than none. `mika2328_the_model_key_is_the_one_settings_reads_for_every_provider` pins that derivation empirically against `Settings::load_for_agent` on **both** doors (config key and env var) for all thirteen providers — deliberately not against `config::CONFIG_KEYS`, which is missing `kimi_model`, `qwen_model` and `zai_model` altogether. `model_source` carries one word the budget sources do not: `unknown_provider`, when a door holds an `llm_provider` this reader cannot parse — reporting `default` there would state "no door carried the model", which is unknown and possibly false. That state is unreachable in production (`Settings::load_for_agent` refuses the file outright), which the test asserts alongside; the reader must stay readable exactly where the loader aborts. The dedup signature covers the model for the mika#2362 reason: an out-of-repo swap moves neither timeout, so a signature blind to it would silence the one line that reports the swap.

**The record, and why it is a value rather than a second resolution (mika#2457).** `resolve_llm_budget_record(agent_id, global_home, agent_home) -> ResolvedBudgetRecord` is the **single constructor** of the resolved pair; `log_llm_budget_resolved` is now `resolve` + `emit_llm_budget_resolved`, and the split exists so `server::init_agent` can **keep** the record it emits instead of walking the cascade twice — two resolutions milliseconds apart being two chances to disagree, with the second one the value nobody would have checked. Every field of the event is on the record, plus one: `resolved_at` (RFC 3339 UTC), which dates the resolution and **is deliberately absent from the dedup signature** — including it would make every resolution a "change" and annul the mika#2293 deduplication outright. That exclusion is pinned by `mika2457_resolved_at_dates_the_record_and_stays_out_of_the_dedup_key`, which **forces** two distinct instants (the second record is the first re-dated by hand) and asserts they differ before asserting the signatures are still equal. The mika#2293 and mika#2280 dedup tests are *not* that control: `resolved_at` is stamped to the second, so two resolutions back to back almost always carry the same string and a leaked key would leave them green.

What the record closes is not a missing fact but an unreachable one. `llm_budget_resolved` already answered *which plafond, which model, through which door* — once per agent per resolved pair, deduplicated, inside a log measured in gigabytes. An operator asking the question on demand had no surface, which is what let mika-arch's `240/900` fail in silence from 2026-09-06 to 2026-09-11, and what swallowed mika#2457: **three** plafonds had been asserted for the same agent — 240 (the checkout), 420 (mika#2342), 300 (mika#2457) — and not one had ever been read off an instrument. A consumer that re-resolved instead of reading the record would report **its own** `process_env`; on a server where a service variable shadows the per-agent `config.toml` that answers the question wrongly, with the authority of a measurement. So the record is resolved once by the process that serves the agent, and every consumer renders it. `mika2457_the_record_has_a_single_construction_site` is a source scan over this crate **and** `mika-agent` refusing a second constructor, allowlist shipped empty — a second one would be a resolver free to diverge, silently, with every behavioural assertion still green (the `grooming_marker` class, mika#2158).

**The cascade is rebuilt, not recorded, and its order is inverted.** Making `load_for_agent` carry provenance would mean instrumenting config-rs for every key to serve two, on the load path of every agent and every binary. So this module redoes the resolution for these two keys only, reproducing the real order — `.env` per-agent > process env > per-agent `config.toml` > global `config.toml` > constant (mika#2218). A reconstruction assuming the usual file-below-env order would report a **false** provenance, which is strictly worse than none: it answers the one question the module exists to settle, with authority, and wrongly. `mika2293_reconstruction_equals_load_for_agent_on_every_cascade_position` pins the duplication by asserting the reconstructed value equals the merged one on all four positions — the day `config.rs` changes that order, it goes red instead of letting the provenance drift. Two further properties are load-bearing: a value living in the process environment is **never** reported `default` (`Settings::effective_llm_http_timeout_secs` falls back to `llm::http_timeout_secs()`, a second out-of-cascade read of the same variable — this reader consults the environment itself, so the two worlds stay separate), and `resolve` **never panics**, which is what lets `mika-agent`'s boot guard read a below-floor value and name the agent instead of aborting the process.

## Typed Errors

- `ClaudeApiError` enum with HTTP status-code retry (429/500/529); `BillingError` variant for non-retriable Anthropic HTTP 400 billing rejections (detected via `error.type == "invalid_request_error"` + message prefix, logs at `error!`, surfaces billing URL in error chain); `BodyRead` variant (mika#2331) for a body cut mid-stream
- Provider-agnostic `LlmError` enum (`Debug + Clone + Error`) with `HttpError`, `Transport`, `ParseError`, `ProviderError`, `UnsupportedFeature` variants

**One error-class vocabulary, one site of definition, two mappings (mika#2331 D3/AC5).** `llm::error::error_class` holds the seven wire-format strings — `transport_timeout` / `transport` / `http_<status>` / `parse` / `provider` / `unsupported` / `other`. They are a wire format, not labels: they land in `audit_events.after_value` (mika#2179's `callback_delivery_failed`) and on the `llm_call_attempt` event, and operators `GROUP BY` them, so a second spelling splits one population without saying so. `LlmError::error_class()` is the mapping; `mika-agent`'s `classify_delivery_error` is now a thin adapter over it (it keeps the two things the LLM client cannot do — walk an `anyhow` cause chain, and answer `other` for a non-LLM failure), and its pre-existing tests are unchanged, which is what attests the format did not shift. `claude::error_class` is a **second mapping** and deliberately not a second spelling: `ClaudeApiError` is foreign to `LlmError` and cannot share an implementation, which is why the shared site is one of *definition*. `BillingError` maps to `http_400` — it is one — rather than inventing an eighth class.

**Body read vs deserialization, on all three rails (mika#2331 AC3).** A failure to **read** the response body means the bytes never arrived: transport, retryable. A failure to **deserialize** a body that did arrive stays `parse`, terminal. mika#2015 made that split on `openai.rs`; `ollama.rs` and `claude.rs` still mapped both to `ParseError`, so every mid-body network hiccup was terminal there. On the Anthropic rail the split alone is not enough: `is_retryable` conditions `Transport` on `e.is_timeout()`, and a cut body is not a `reqwest` timeout (`unexpected EOF` / `decode` / `reset`) — hence the dedicated `BodyRead`, retryable **unconditionally**, rather than widening `Transport` to `=> true` (which would also have made a refused connection retryable, a change nothing measured). `BodyRead` also counts as transport for the mika#1744 fast-retry threshold, via `is_transport_class` — **the quietest omission in that file**: forgetting it breaks no test and shows no symptom, only a retry chain abandoned earlier than it should be. The same mika#1744 threshold was ported to `ollama.rs`, where it was missing outright.

**`llm_call_attempt` (mika#2331 AC2).** One ungated INFO event per attempt, on all three rails, carrying `provider`, `model`, `attempt`, `max_attempts`, `elapsed_ms`, `outcome` ∈ {`success`, `retrying`, `exhausted`, `deadline_abort`}, `error_class` and `http_timeout_secs`. It answers the question a hung turn could not: *did the chain run once or four times?* The Anthropic rail emits it from **inside `claude.rs`'s own loop**, below the `LlmProvider` boundary, because `anthropic.rs` flattens every error off that rail into `LlmError::ProviderError` — an event emitted above it would report `provider` for a transport timeout, a false line rather than an absent one. All three rails are instrumented including the two carrying no measured hang, so a missing line means "this call did not retry" and never "this rail is not instrumented". The procedure that reads it is in the workspace `CLAUDE.md` § *Lire un hang LLM « 420 s sans octet »*.

**One retry predicate, read by nine sites (mika#2362).** `llm/retry_gate.rs` owns the answer to *"will a further attempt run?"*. Three sites per rail asked it and they were **not the same question**: the deadline guard read the remaining margin against a class-dependent threshold; the `outcome` line read the budget and the error class and **never the deadline**; the post-loop error message re-derived the guard's threshold a third time, under a comment saying it did so *"so the two branches agree"* — an agreement obtained by copying. Measured 2026-09-17 on mika-arch under a `300/600` geometry: `outcome="retrying"` on an attempt cut at exactly the 300 000 ms plafond, then the turn erred **18 ms later** with no second attempt anywhere. `600 − 300 = 300` is exactly the non-transport threshold (`0.75 × cap + 0.25 × cap = 1.0 × cap`), so the margin was zero and the guard refused what the outcome line had just promised. The same copy-drift had already been measured once and cost two tickets: mika#2331 §3.3 found mika#1744's transport threshold *"had never been ported"* to the ollama rail.

`RetryThresholds::from_budget` is the **only** site in the crate where the non-transport sum is written; `retry_gate::tests::mika2362_no_rail_recomputes_the_retry_threshold_inline` is a source scan with an **empty allowlist** that refuses a sixth one. It targets the sum, not the accessors — `budget.rs` defines those and asserts them in its own tests, so forbidding `typical_call_duration_secs()` alone would make the defining module violate its own guard; an accessor read on its own decides nothing. The Anthropic rail, which carries no `LlmTimeoutBudget` and hands `reqwest` the literal `ANTHROPIC_HTTP_TIMEOUT_SECS`, reads `RetryThresholds::pinned_at_default_cap()` — the default budget's thresholds, valid because that literal *is* the default cap, and pinned as such by `claude::tests::mika2362_anthropic_cap_is_the_default_cap` so the substitution cannot outlive its premise. `ClaudeApiError` reaches the predicate through a local `RetryClass` adapter: the same shape `error_class` had to take, two mappings over one site of definition.

**Wire-format shift, dated 2026-09-17 (mika#2362).** An attempt refused by the deadline now reports `outcome = "exhausted"`, where it used to report `retrying`. A `GROUP BY outcome` therefore moves population from `retrying` to `exhausted` at deploy — **that move is the correction, not a side effect**. `deadline_abort` is untouched and keeps its invariant (`elapsed_ms = 0`, the attempt that did not happen); the refused attempt reported here *ran*, for 300 s in the founding incident, so calling it `deadline_abort` would break that invariant, while `exhausted` already documents "the attempt budget is spent" — and a budget that can no longer fit a call before the deadline is spent. **The control flow is unchanged**: same `break`, same `continue`, same `max_attempts`, same `worst_case_failure_secs`. Only the line's honesty moved.

**`effective_max_attempts` — the count that is reachable, reported and never enforced (mika#2362 D4).** `max_attempts` is `floor(envelope / cap)`, arithmetic with zero overhead; the guard measures a real clock and refuses at `remaining < 1.0 × cap`, so after an attempt consuming the full cap the margin is `envelope − cap − ε` with `ε > 0` always. **Whenever the envelope is an exact multiple of the cap, the last nominal attempt is unreachable** — 300/600 is the `k = 2` case of that family, not a peculiarity of 300. `llm_budget_resolved` gained `effective_max_attempts` and `retry_reachable`, and a `llm_budget_retry_unreachable` WARN fires when they diverge. **It must not replace `max_attempts`**: the transport class clears the smaller `0.50 × cap` threshold and really does get its second attempt, so sizing the mika#2342 watchdog on the effective count would take it from 660 s to 360 s at that geometry and cut a legitimate transport chain — a guaranteed false positive on a mechanism whose value is its silence. `budget::tests::mika2362_worst_case_is_unchanged_by_the_effective_count` exists to make that swap go red. No geometry value moved in mika#2362; the setting decision belongs to the operator, with the measurement in hand.

**The retry loop has tests, since mika#2331 and not before.** `crates/mika-common/tests/llm_retry.rs` — eleven cases against a real HTTP server. `MockLlmProvider` could not produce them: it does not override `send_message_with_deadline` and returns its error without a loop, so it can say what an error *is* and never how many times the client asked. The server is a hand-rolled `TcpListener` rather than `wiremock` for one reason: the fixture is a body **cut mid-stream**, and `hyper` computes `Content-Length` from the body it is given and holds the connection open — a mismatched header would hang the client until its HTTP timeout instead of producing the `unexpected EOF` under test. `ClaudeClient` gained a `base_url` field (always `API_URL` in production) and a `for_test` constructor behind the existing `test-utils` feature: it posted to a hard-coded constant, which is also the explanation for that rail's loop having never been covered.

## Prompt Caching (Anthropic)

`to_anthropic_request()` in `anthropic.rs` injects `cache_control: {"type": "ephemeral"}` breakpoints on system prompt (`SystemContentBlock`) and last tool definition (`CachedToolDefinition` wrapper via `#[serde(flatten)]`). Two of four allowed breakpoints used. Cache metrics (`cache_read_input_tokens`, `cache_creation_input_tokens`) logged at info level in `ClaudeClient::send_message_inner()` and persisted to `llm_calls` table (`cache_read_tokens`, `cache_write_tokens` columns). Provider-agnostic types (`LlmRequest`, `LlmMessage`) unchanged — cache *injection* is Anthropic-specific. `OpenAiCompatibleProvider` parses `prompt_tokens_details.cached_tokens` from OpenAI-standard responses into `cache_read_input_tokens` (logged at info level, persisted to `llm_calls`); `cache_creation_input_tokens` remains `None` for OpenAI-compatible providers (not reported by the OpenAI API). OpenRouter Anthropic models go through `OpenAiCompatibleProvider` and do not get prompt caching injection but do report cache read metrics if the upstream provider auto-caches.

## Internal Tag Stripping

`strip_internal_tags()` in `mika-common::llm` removes echoed internal XML tags (`<context>`, `<callback_result>`, `<task-health>`, `<rewind_reversals>`, etc.) from LLM response text before display and persistence. Applied at `run_loop()` EndTurn extraction, continuation responses, and the `send_message` tool. Uses lazy-compiled per-tag regexes with early-exit fast path when no `<` present. Closing-tag matching tolerates malformed variants from non-Anthropic models (#453): whitespace (`< /tag>`, `</ tag>`) and bare (`tag>` without `</`). System prompt also instructs the LLM not to echo internal tags (defense-in-depth).

## XML Tool Call Extraction

`extract_xml_tool_calls()` in `mika-common::llm::openai` recovers tool calls when OpenAI-compatible providers emit them as XML text (`<function=name>args</function>` or `<tool_call>...</tool_call>`) instead of structured `tool_calls`. Integrated into `from_openai_response()` — runs only when no structured tool_calls are present, converts XML to `LlmResponseContent::ToolCall`, flips `stop_reason` to `ToolUse`. Uses lazy-compiled regexes (`LazyLock<Regex>`). Defense-in-depth: `detect_text_based_tool_call()` in `agent.rs` catches patterns that slip through Layer 1, re-prompts the LLM once (similar to `required_tools_retry_done` pattern). See #447.

## MockLlmProvider

`llm/mock.rs` — sequence-based mock for deterministic agent loop testing, gated behind `test-utils` feature (`#[cfg(any(test, feature = "test-utils"))]`). Used by the eval harness in `crates/mika-agent/tests/eval/`. Responses stored in `Mutex<Vec<MockResponse>>` for dynamic replacement via `clear_and_set()` — enables tests that need to seed DB data (generating IDs) before configuring mock responses that reference those IDs. Must be called before `.run()` (not safe during concurrent access). `MockLlmProviderBuilder::health_error(LlmError)` configures `check_health()` to return the given error on every call (default: `Ok(())`), enabling degraded-provider scenario testing.

**`MockResponse::Delayed { sleep_ms, inner }` variant (#848):** wraps an inner response with a virtual `tokio::time::sleep(Duration::from_millis(sleep_ms))` before resolving. Pair with `tokio::time::pause()` + `start_paused = true` on the test to drive the clock without wall-clock waits — used by the deadline-during-LLM-call eval scenarios in `tests/eval/test_deadline_in_flight_llm_call.rs`. Always uses `tokio::time::sleep` (never `std::thread::sleep`, which would block the runtime and defeat virtual-time control). Nesting `Delayed` inside `Delayed` panics at resolve time; push multiple `Delayed` entries onto the response sequence instead. Helper constructor: `delayed_response(sleep_ms, inner)`.

`Settings::test_defaults()` — minimal `Settings` constructor for deterministic tests, gated behind `test-utils` feature. Lives on `Settings` itself so new field additions produce a compile error at the canonical location. Used by the eval harness and `mika-agent::test_utils::dummy_settings()` (which delegates to it).
